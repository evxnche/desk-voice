Desk Pal · ESP32 voice gadget

How the desk gadget controls my Mac

You say “gee gee, lock my Mac” to a little screen on the desk, and the Mac locks. The cloud never talks to the Mac directly: the gadget passes the command to a small helper on the Mac over the home Wi-Fi.

One command, start to finish

  1. On the board Hears “gee gee” The wake word is recognised on the chip itself, then it records you and streams the audio up as you talk.
  2. On the server Decides what to do Speech to text, then a language model with tools. A Mac tool doesn’t act; it adds a command to the reply.
  3. On the board Speaks and forwards Plays the spoken answer and sends the command to the Mac over the local network.
  4. On the Mac Does it A Python helper runs it with built-in macOS tools: AppleScript, pmset, pbcopy.

The three parts

The board

Waveshare ESP32-S3 with a 4.2″ reflective LCD, running MicroPython on custom firmware. Wake word via Espressif’s on-device speech model. It also runs a tiny web server on the home network.

The voice server

One serverless function on Vercel. Grok speech-to-text, an open-weights GPT model for the reasoning and tool calls, Grok text-to-speech, all through Vercel’s AI Gateway.

The Mac helper

One Python file, standard library only, kept running by a launchd agent. It listens on a local port and checks in with the board every minute.

How the board knows where the Mac is

The Mac sits behind the home router, so nothing on the internet can reach it, and that’s on purpose. Instead the helper reaches out: every 60 seconds, and straight away when something changes, it sends the board its own address on the Wi-Fi plus a short status (what each recent Claude Code session is doing). It finds the board by its local name, deskpal.local.

The board remembers the address. If the Mac hasn’t checked in for 3 minutes, the board treats it as asleep or away. Each time you ask a question, the board tells the server whether the Mac is online, so the model only offers Mac actions when they can actually work.

Walkthrough: “gee gee, lock my Mac”

  1. The board recognises the wake word, records until you stop talking and uploads the audio while you’re still speaking, so little is left to send at the end.
  2. The server transcribes it. The model calls the mac_control tool with {"action": "lock"}. The tool doesn’t touch anything; it adds {"do": "mac", "action": "lock"} to the list of commands that goes back with the spoken reply.
  3. The board plays the spoken reply (“Locking your Mac”) and posts the command to the helper: POST /do with a shared secret key. It does this on a background thread, so a slow or sleeping Mac doesn’t hold up the gadget.
  4. The helper runs pmset displaysleepnow. Turning the display off locks the Mac, because its screen lock is set to “immediately”.
  5. If anything fails, the helper tells the board, and the Pal says “Sorry, I couldn’t do that on your Mac.”

What it can do

“open ezwrite”Fuzzy-matches the name against the installed apps and a short list of sites (so a transcription like “Easy Right” still works), then opens the app, or the site as a new tab in Arc

“search YouTube for …”Opens the results page

There’s also a procrastination cop: every few seconds the helper notes the app and site in front. After 15 minutes of YouTube or X during work hours, the Pal glares and tells you off.

Dictation mode

Dictation types what you say into whatever app is in front on the Mac.

  1. Turn it on: “gee gee, dictation mode”. After transcribing it, the server spots the phrase with a simple pattern match, before the language model is involved, answers “Dictation on”, and tells the board to switch dictation on.
  2. Talk while holding the button. In dictation mode, recordings made by holding the board’s KEY button are marked as dictation. The server skips the language model completely: it transcribes and sends back one command, type, with the text. The board just beeps.
  3. The Mac pastes it. The helper saves the current clipboard, puts the text on it, presses Cmd-V through System Events, waits half a second and puts the old clipboard back. Pasting beats simulated keystrokes: it’s instant and handles any character.
  4. Turn it off: “gee gee, stop dictation”, or just leave it. It switches itself off after 10 minutes without a dictated line.
def type_text(text):
    before = pbpaste()                      # keep the clipboard
    pbcopy(text)
    osascript('tell application "System Events" to keystroke "v" using command down')
    time.sleep(0.5)
    pbcopy(before)                          # and put it back

Why dictation uses the button

The wake word still works during dictation, so “gee gee, stop dictation” always gets through. Typing only happens while you hold KEY, so a conversation in the room never ends up in your document. For a single line there’s a shortcut: “gee gee, type see you at five”.

Security and permissions

  • The Mac is only reachable from the local network, and the cloud server never connects to it.
  • Every request between the board and the helper carries a shared secret key. The helper rejects anything else, and its log never prints the key.
  • macOS asks once for each permission: Accessibility (for the Cmd-V typing), Screen Recording (for “what’s this error?”), and control of System Events and the browser.
  • Every Mac action is a fixed command the helper knows. The model can only choose which one to run and what to pass to it, never run anything of its own.
Built with MicroPython on an ESP32-S3, a Node serverless function on Vercel (AI SDK and AI Gateway), and the Python standard library on the Mac.
